**What changed**
Pushed the batch pagination (`ORDER BY key LIMIT $2`) inside the individual `SELECT` arms of the `UNION ALL` Common Table Expression (CTE) in `fetch_delivery_kv_guard_batch_pg`. Enclosed each query in parentheses to satisfy PostgreSQL syntax.

**Why**
Previously, PostgreSQL would scan, evaluate, and extract all remaining matching index entries across both `kv_meta` search paths into memory before filtering and truncating the combined result to `$2` rows. This created an O(N) database scan latency bottleneck when reconciling extensive dispatch activity. By pushing the limits down to the index lookup itself (where `key` is effectively monotonic and deterministic), the query avoids massive allocation and scan overhead, achieving an O(K) complexity reduction where K is the limit constraint.
