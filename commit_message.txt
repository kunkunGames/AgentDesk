Bolt: optimize agentBusy SQL query with EXISTS pattern

What changed:
Modified the `agentBusy` calculation in `policies/lib/auto-queue-lifecycle.js` to use `SELECT 1 ... LIMIT 1` instead of `SELECT COUNT(*)`.

Why:
The previous query performed a full table or index scan to count all matching rows. By changing it to an existence check (`SELECT 1 ... LIMIT 1`), the database can short-circuit and return as soon as the first matching row is found, converting an O(N) operation to O(1) in the best and average cases.
