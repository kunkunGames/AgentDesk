Bolt: optimize normalize_dispatch_summary_text allocation

What changed:
Rewrote `normalize_dispatch_summary_text` in `src/dispatch/dispatch_summary.rs` to eliminate O(N) intermediate `String` and `Vec` allocations during word splitting. The new implementation lazily iterates through the string, writing directly to a pre-allocated, bounded `String` and stops execution entirely once it hits `MAX_DISPATCH_SUMMARY_CHARS`.

Why:
This function is on the hot path for fetching dispatch summaries and querying task listings. The previous implementation allocated an entire string representing the whitespace-joined input and placed it into a `Vec` before applying character truncation. This scales linearly in both time and space relative to the raw, potentially massive log file inputs. The fix guarantees O(MAX) limit behavior with no multi-pass buffering.
